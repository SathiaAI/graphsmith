## Headline
v0.4.0 hardens the **trust surface**: the deferred review gaps become enforced, recomputed controls, and the GSA verifier learns to check them. Each run-time claim a bundle makes — that capabilities stayed within grant, that external effects reconciled, that the signer is trusted, that the trace was redacted, that the build has provenance — is now **recomputed from the bundle's own evidence and fails closed on any lie** (D5). Evidence, **not** certification.

## What's new
- **Capability conformance (R1)** (`checks/v040-caps.js`): per-skill filesystem / model / subprocess / network grants; requested ⊆ granted with segment-boundary path containment; a class is attested only when the engine actually enforces it (D1). `skill_id` is identity — evidence, never a decision input (C1).
- **Side-effect receipts (R2)** (`checks/v040-receipts.js`): recorded external effects reconcile against adapter receipts; an evidence-less "success" (no external_id) is treated as unknown and never vouched for; a malformed receipt fails closed.
- **Signer lifecycle + attestation recall (R3)** (`checks/v040-signer.js`): a revoked signer and a recalled bundle (exact bundle_id + manifest_sha256) fail closed; a rotated key verifies only if the chain resolves to a live successor (cycle / dangling / rotated-into-revoked fail closed); an unknown signer is unavailable.
- **Secret / PII redaction (R4)** (`checks/v040-trace.js`): an exported trace carrying an unredacted secret, credential, or PII fails closed in every mode; a recall gate over a declared 17-format battery guards against regression (metadata-only bodies rejected too).
- **SBOM + build provenance (R5)** (`checks/v040-provenance.js`): the SBOM digest and provenance subject are recomputed and matched against the actual artifact hashes (never trusted as declared, D5); tamper / forged-subject / stray-material / incompleteness fail closed. Ships toward `npm publish --provenance`.
- **Policy-as-code (R8)** (`checks/v040-policy.js`): versioned, declarative enterprise-safe profiles; a required control counts only when enforced; an unknown profile and a forbidden-yet-enforced control fail closed; policies round-trip through a canonical form.
- **GSA §9.11 extended-control integration** (`scripts/gsa-verify.js`): the verifier recomputes all five run-time controls from a bundle's own evidence and fails closed on any control-lie. Additive and backward-compatible — a v0.3.0 bundle without `control_attestations_v040` verifies unchanged. SPEC bump: `SPEC-CHANGES.md` `[0.3-draft]`.
- **`graphsmith verify` CLI** (`scripts/graphsmith-cli.js`): a fail-closed verifier bin shipped from the `graphsmith-skill` package for CI and enterprise verifiers — `graphsmith verify <bundle.json> [--keys <keys.json>]`; without trusted keys, authenticity is unavailable and the bundle fails.
- **Independent Assurance program** (`docs/ASSURANCE.md`): the ≥2-non-Anthropic posture formalized into a citable program (Cycle 1, v0.4.0 controls) — reproducibility runs, verifier cross-validation against the published conformance vectors, and a reviewer-engagement recipe.

## Adversarial review (dissent preserved)
Every control was built by one model family (claude-opus) and adversarially tested by **≥2 different, non-Anthropic families** (Mistral, DeepSeek, Qwen); the orchestrator re-ran every suite and audited zero/low-finding results for rubber-stamping. Real defects found and fixed this cycle include: the R4 redaction battery **missing AWS secret keys / JWTs / Google & Stripe keys / high-entropy tokens / phone PII** (a leaky trace would have verified) plus two regex-brittleness bugs; the R5 SBOM digest folding in a non-content `bytes` field; R1 path-prefix traversal and a `skill_id` C1 conflict; R2 evidence-less success; R3 corrupt/duplicate registry entries. Every one re-verified.

Two process catches worth naming: a tester (Mistral, R4) shipped an **inverted harness that scored missed leaks as passes** — its 22/22 was rejected as an invalid zero-finding and the real signal came from an independent probe + DeepSeek; and a clean **28/28** on R8 and on the §9.11 council was **audited** (sound pass criteria, correct-direction attacks) rather than trusted. The §9.11 integration itself — an edit to the constitutional `gsa-verify.js` — went through the same council; DeepSeek 28/28 (audited genuine) and an orchestrator fail-open probe confirmed it never over-attests. Per-component trails in each `tests/**` `ADJUDICATION.md`.

Closed by a gauntlet: **395 scenarios, all HOLD, 0 BREAK** (`tests/gauntlet/v0.4.0-battery.js`; 28 adjudicated tester false-positives documented), with the v0.3.0 gauntlet still green (286). GSA conformance: **14/14 vectors** (4 new §9.11 vectors). Both gauntlets are wired as the gating CI regression step.

## Compatibility
- **Backward-compatible.** A v0.3.0 GSA bundle verifies unchanged; the five extended controls are optional and declared-only. `control_attestations_v040` + its evidence keys are opt-in.
- `schema_version` is unchanged for existing artifacts; the five new schemas (`capability-grant`, `side-effect-receipt`, `signer-registry`, `attestation-recall`, `redaction-policy`) are additive.
- Zero runtime dependencies; Node ≥ 18; no clock / randomness / network in any decision path.

## Known limitations
- The redaction battery is a recall-measured floor, not a guarantee of zero leakage: base64-encoded, cross-field-split, sub-threshold, and bare-IP cases are outside the declared format set (documented in `tests/v040/trace/ADJUDICATION.md`).
- Keyless / transparency-log signing remains opt-in and network-disclosed; the local-keypair default is unchanged.
- The independent-assurance program's external-reviewer roster and milestone naming are owner-set.
