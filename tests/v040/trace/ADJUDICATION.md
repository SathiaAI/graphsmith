# v0.4.0 Lane R4 — graded trace_mode + secret/PII redaction battery — adversarial adjudication

**Target:** `checks/v040-trace.js` · **Builder:** claude-opus (Anthropic) · **Platform:** win32, Node v24.18.0 · **Testers (≥2 non-Anthropic):** Mistral-Large + DeepSeek-v3.1 (OpenRouter code-gen). Qwen-2.5-72B returned an empty completion and Qwen-2.5-Coder truncated to a broken stub; both were discarded and DeepSeek substituted. Builder ≠ testers. Orchestrator re-ran both suites and ran an independent recall probe.

## Tester-harness correction (Mistral) — a zero-finding that was invalid
Mistral's raw run reported **22/22 PASS** (zero findings). That result was a **rubber-stamp**, not a clean bill: its runner used `if (result)`, but every leak-bypass test returned a truthy **diagnostic string** (`"AWS secret key leaked but passed"`, …) on the *leaked-but-passed* path — so a **missed leak scored as PASS**, inverting the verdict. Under the no-self-certification rule a zero-finding review is invalid; the orchestrator did not accept it. The harness was corrected to `if (result === true)` (a faithful fix of a harness-contract bug — author intent was unambiguously *leaked = fail*, per the diagnostic strings), after which Mistral surfaced real findings. The genuine recall signal came from the **orchestrator recall probe** (calling `scanLeaks` directly on hard formats) and from **DeepSeek**.

## Real defects found + fixed
1. **Recall gaps in the pre-test battery (HIGH) — orchestrator probe + both families.** The 11-pattern pre-test battery MISSED AWS 40-char secret access keys, JWTs, Google API keys, Stripe keys, high-entropy 40+ char tokens, and phone PII — a trace carrying any of them wrongly `verified` (a leak reaches "verified"). **Fixed:** battery expanded to 17 patterns (added JWT, Google, Stripe, high-entropy token, hex-40, UK National Insurance, US + E.164 + spaced-intl phone), and the `--selftest` recall gate was widened to exercise all of them (**17/17 = 100%**, threshold ≥95%) so a regression fails CI.
2. **Google-API-key regex brittleness (MEDIUM) — DeepSeek `google-key-bypass`.** `/AIza[A-Za-z0-9_-]{35}\b/` matched only *exactly*-35-tail keys; a longer key escaped because the trailing `\b` cannot sit inside a word-run and the fixed `{35}` cannot extend. **Fixed → `{35,}`.**
3. **High-entropy-token regex brittleness (MEDIUM) — DeepSeek `generic-b64-bypass`.** Same defect class: `/[A-Za-z0-9+/]{40}\b/` matched only *exactly*-40-char runs, so a 42-char token slipped through. **Fixed → `/[A-Za-z0-9+/]{40,}/`.**
4. **Spaced international phone gap (LOW) — DeepSeek `phone-bypass`.** The contiguous-digit E.164 pattern missed `+44 20 7946 0958`. **Fixed:** E.164 pattern broadened to allow separators (`/\+\d[\d ().-]{7,}\d/`).

## Adjudicated NOT defects (declared recall/precision boundary + inert input)
A pattern battery is a **recall-measured floor, not proof of zero leakage** (stated in the check's own assumptions and consistent with the honest-language rule). The following residual FAILs sit outside the declared set or are fail-closed-safe by design:
- **generic-hex-token `"a"×32` (Mistral).** Below the 40-char high-entropy threshold and a degenerate single-char string; catching 32-char runs would flood false positives on MD5/UUID/request-ids that pervade legitimate traces.
- **secret-spread-across-fields (both).** A secret split across separate JSON fields — cross-field reassembly is out of scope for a stateless pattern battery. Documented limitation.
- **base64-encoded-secret (both).** A sub-40-char base64 blob of a short secret; arbitrary base64 is indistinguishable from legitimate encoded data.
- **ipv4-as-pii (both).** A bare/private (RFC1918) IP is not a secret/credential and appears throughout legitimate traces (localhost, service IPs).
- **bigint-trace (DeepSeek).** A non-string `trace` is coerced with `String()` and scanned — this is *fail-closed-safe*: a `toString`/`valueOf`-secret **is** caught (DeepSeek's own `object-toString-secret` passed). A BigInt stringifying to a non-secret is legitimately clean; DeepSeek's "non-string → failed" expectation is stricter than the (safe) design.
- **proto-pollution (DeepSeek).** Inert `__proto__` on an otherwise-clean trace; identity-invariant (C1) — same class as the R1–R3 proto-pollution adjudications.
- **hostile-getter (DeepSeek `actual=verified`).** Ground-truthed directly: the live check returns **failed** (the throwing getter is caught and fails closed), and Mistral's `crash-hostile-getter` passed. DeepSeek's harness mis-recorded the verdict — a tester-harness artifact, not a check defect.

## Verdict
**Lane R4 TEST-PASSED.** Two non-Anthropic families. Mistral's inverted harness was corrected (its zero-finding was invalid and rejected); one HIGH recall gap and two MEDIUM regex-brittleness defects were fixed, plus a LOW phone gap; the permanent `--selftest` recall gate now locks in 17 formats at 100%. Properties under executed attack: a trace carrying any battery-covered secret/PII/credential fails closed in every mode; `metadata-only` carrying payload fields fails closed; an invalid `trace_mode` fails closed; malformed input (null / non-string / BigInt / hostile getter / proto-pollution / proxy) never throws (C2) and coercion is scan-covered; the verdict does not read timestamps or identity as decision inputs (C1). Declared limitation: the battery is a recall floor — base64 blobs, cross-field-split secrets, sub-threshold tokens, and bare IPs are outside the declared set, never claimed as caught.
