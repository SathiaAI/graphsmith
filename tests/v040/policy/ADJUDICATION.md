The assertions are correct-direction and adversarial, so the clean pass is genuine.

## Adjudicated NOT defects (Mistral's 3 FAILs — verdict correct, reason-string over-specification)
Mistral's suite asserts specific `reason` **substrings** on top of the verdict; the verdict is the security property and is correct in all three:
- **`null-context`.** `run(null)` fails closed with reason `"policy not an object"`; Mistral expected the substring `"no context"`. Both are `failed`. `run()` normalizes a null ctx to `{}` (the shared R1–R4 wrapper pattern), after which "there is no policy" is the accurate reason. The verdict (fail-closed) is correct; the exact wording is evidence, not the decision.
- **`hostile-getter-control` / `proxy-controls`.** A `controls` map whose control access **throws** fails closed globally (reason `"exception — failing closed"`); Mistral expected the substring `"unenforced"` (i.e. treat the throwing control as merely absent). **Deliberately not adopted:** treating a throwing control as "unenforced" is *less* safe — a **forbidden** control hidden behind a throwing getter would then evaluate as not-enforced and slip through as an over-permit. Failing the whole verdict closed on a hostile control map is strictly stronger. DeepSeek's equivalent `CRASH_HOSTILE_GETTER` asserts only non-throw (a returned status), which this behavior satisfies.
